# UE5 experiment audit, 2026-09-28

Baseline: `master` at `b0a7062`. Companion audit in AnimeRPG:
`Docs/Audit/ENGINE-AUDIT-2026-09-28.md` on branch `claude/loving-clarke-el24od`.

Lucas asked for the AnimeRPG / AnimeRPG-UE5 pair to be audited and for the game
engine to reach UE5-class capability while keeping the game's special features.
Under ADR-0001 in AnimeRPG, the production runtime stays the custom Astral
Engine. That work landed there. This repository stays the reference experiment,
and this note records its gaps. **No Source/, Config/, .uproject or engine-version
change is made here** (AGENTS.md: engine and scope changes need Lucas's approval).

## Findings

1. **Legacy input system.** `SetupPlayerInputComponent` uses `BindAxis` and
   `BindAction`, and `Config/DefaultInput.ini` defines axis and action mappings.
   UE 5.1 and later deprecate these in favour of Enhanced Input (Input Actions
   plus Mapping Contexts). `Scripts/validate_project.py` currently asserts the
   legacy bindings, so a migration is a contract change: update the validator
   and its tests in the same approved task.
2. **Dash does not follow the game's rules.** `Dash()` calls
   `LaunchCharacter(direction * 1200)` on Left Shift. It has no cost, cooldown or
   fixed distance. In the game, Shadowblade Dash is Q, costs 25 of 100 resource,
   has a 1 s cooldown and travels 6 m. Left Shift is Guard there.
3. **No playable content defaults.** There is no default map, skeletal mesh,
   Animation Blueprint or level. `PrimaryActorTick.bCanEverTick = false` is fine
   for now.
4. **Special features absent.** Light and heavy attacks, guard and Fatal Strike,
   Thought Commands with Focus x0.35, the National Mall landmarks and the
   Lincoln encounter do not exist here.
5. **No native evidence.** Only the source-relationship validator runs in CI. No
   UnrealHeaderTool, compile, Play In Editor or package run is recorded.

## Recommendation (needs Lucas's approval before any source change)

If a UE5 track is wanted, avoid re-implementing the rules in Blueprints or in a
second C++ copy:

1. Compile AnimeRPG's engine-free `Engine/Scene` domains (`CombatSandbox`,
   `ShadowbladeActions`, `ThoughtCommands`, `LandmarkInteraction`,
   `LandmarkEncounter`, `WorldBlockout`) into a plain C++ module.
2. Drive those domains from a thin `ACharacter`/`AGameMode` layer, so both
   engines share one rule set and the domain tests stay authoritative.
3. Migrate to Enhanced Input with the game's bindings (WASD, J/K, Q/L, Shift,
   1–5, E) and update the validator contract.
4. Record native evidence (build, Play In Editor, packaged launch) before
   claiming anything beyond source checks.
