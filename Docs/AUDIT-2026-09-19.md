# UE5 experiment audit, 2026-09-19

Baseline: master at `98fc268cc4515e26a3a4a45158ca255cf0e7768d`.

## Role and history

This is the small third-person Unreal experiment, not the custom Astral Engine
production project. July 31 history shows the initial scaffold and a repair of
its module layout, target rules, game mode, and character. The August 23 README
clarified the experimental role. No later default-branch implementation was
observed at audit start.

The checked-in slice has a character, spring-arm camera, controller-relative
movement, jump, and launch-based dash. It has no checked-in game level, production
art, combat loop, cooked distribution, or proof of the full RPG vision.
EngineAssociation is 5.8 in this source, not a claim about the latest public engine.

## Findings and repairs

No concrete gameplay defect was reproduced in the inspected source. Missing
verification coverage was real: there was no automated suite or CI contract gate.
The candidate adds an engine-free checker, ten regression tests, source-only CI,
an installed-engine version preflight, and explicit agent/validation boundaries.
No Source/, Config/, .uproject, or existing engine choice change is made.

Checks cover module rules and both target relationships, legacy input bindings
and mappings, game-mode/native-pawn selection, malformed metadata, and optional
Build.version compatibility. These are lightweight source checks, not full C++ or
INI semantic validation; comments/macros and runtime overrides remain native-review concerns.

## Executed evidence

Eight input files were copied from GitHub responses into an isolated fixture and
matched their returned Git blob SHA values. This was not a complete cloned project.

- `python Scripts/validate_project.py`: PASS, exit 0.
- `python -m unittest discover -s Tests -p "test_*.py" -v`: 10 tests PASS, exit 0.
- Version checks used synthetic installed-engine fixtures only. No real Unreal
  installation, compiler, Editor, or packaged build was available in this audit.

Hosted source-only CI, native Game/Editor builds, interactive behavior, packaging,
and independent review are distinct gates. Check actual PR runs for hosted results.
This report does not claim native acceptance or approve a merge.

## Next work

Keep the experiment separate. For an explicitly approved UE task, first verify
an actual installed engine against the descriptor, compile both targets with
recorded exit codes, then validate movement/camera/jump/dash in a suitable editor
scene. Do not treat a Game target as a cooked release or use this as permission
to restart paused production-game content in the Astral Engine project.
